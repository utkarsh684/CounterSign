# COUNTERSIGN: Security Risk Register & Threat Model

| Risk ID | Threat Category | Description | Severity | Countermeasure in Countersign |
| :--- | :--- | :--- | :--- | :--- |
| **SEC-01** | Prompt Injection in Invoices | Malicious invoice containing adversarial prompt instructions to redirect payment to attacker IBAN/PayPal. | **CRITICAL** | **Multilayer Isolation**: (1) Invoice text treated as untrusted data, never as system instructions. (2) Strict schema extraction. (3) Deterministic policy engine checks payee registry; unauthorized email triggers instant hard DENY. (4) Independent AI Verifier scans specifically for instruction alteration & injection. (5) Human authorization required. |
| **SEC-02** | Autonomous Credential Abuse | AI agent abuses PayPal client secrets or bearer tokens to execute unauthorized payouts directly. | **CRITICAL** | **Credential & Tool Isolation**: AI agents are never given PayPal credentials or payout tools. Agents only possess `request_payment()`. Only backend `PayPalExecutor` holds credentials and communicates with PayPal Sandbox. |
| **SEC-03** | Spending Cap Race Conditions | Concurrent agent payment requests bypass daily or weekly spending limits via race condition. | **HIGH** | **Database Concurrency Control**: Payout limits are evaluated within atomic serializable/repeatable read transactions with pessimistic `SELECT ... FOR UPDATE` locking on user limit counters. |
| **SEC-04** | Webhook Forgery & Replay | Attacker crafts fake PayPal payout success webhooks or replays past events to manipulate status. | **CRITICAL** | **PayPal Webhook Verification**: (1) Exact validation of `PAYPAL-TRANSMISSION-ID`, `PAYPAL-TRANSMISSION-TIME`, `PAYPAL-TRANSMISSION-SIG`, `PAYPAL-CERT-URL`. (2) Official PayPal `verify-webhook-signature` REST endpoint verification. (3) Deduplication by `paypal_event_id`. |
| **SEC-05** | Audit Log Tampering | Rogue administrator or compromised server alters audit logs to conceal fraudulent activity. | **HIGH** | **SHA-256 Hash Chaining**: Every audit entry commits to the cryptographic hash of the previous record. The frontend and backend run an automated chain-verification algorithm that flags broken links immediately. |
| **SEC-06** | Currency Precision & Rounding | Floating-point rounding errors lead to drift or limit bypass. | **HIGH** | **Integer Minor Units**: All monetary values are represented strictly as 64-bit integers (e.g. cents) with explicit ISO 4217 currency codes. No floating-point math in financial policies. |
| **SEC-07** | Stale or Revoked Mandate Abuse | Agent attempts payment against an expired, deactivated, or revoked spending mandate. | **HIGH** | **Real-time Mandate State Check**: Pre-flight policy checks re-verify mandate status (`ACTIVE`), version match, and HMAC signature before submission and immediately before PayPal execution. |
| **SEC-08** | Global Emergency / Rogue Agent Loop | Agent enters rapid loop submitting hundreds of payment requests. | **CRITICAL** | **Hardware-Style Kill Switch & Rate Limiter**: Account owner can toggle immediate global kill switch which rejects all incoming gateway requests and halts pending executions immediately. |
| **SEC-09** | Live-Money Accident in Sandbox | Developers or users accidentally execute live financial transactions during testing. | **CRITICAL** | **Sandbox Environment Lock**: Base URL is strictly locked to `https://api-m.sandbox.paypal.com`. Clear `SANDBOX` indicators across UI and rejection of non-sandbox configurations. |
